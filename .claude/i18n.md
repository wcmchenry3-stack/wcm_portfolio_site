## Feature Flag: `VITE_ENABLE_TRANSLATIONS`

Non-English locales are **off by default** (`src/config/features.js`). With the flag off, i18next pins `lng: 'en'` (ignoring the browser language and any saved `i18n-locale`), `supportedLngs` is `['en']`, and the Navbar hides the `LanguageSwitcher`. Set `VITE_ENABLE_TRANSLATIONS=true` in the Render dashboard and redeploy to turn translations back on. It is a build-time Vite variable, so a change needs a new build. Turn it on only once every locale is caught up with the English (`node scripts/check-i18n-strings.js`).

The static `hreflang` links in `index.html` and `public/sitemap.xml` are unaffected by the flag.

## Translation Philosophy

This site uses a **marketing-first** translation approach — not literal. See [translation-philosophy.md](translation-philosophy.md) for the full brief: PM brand positioning, tone principles, hybrid term guidance, and how to update the prompt.

## Namespaces

- `common` — navbar, footer, shared date labels
- `home` — hero (incl. proof-point stats), selected work, leadership/coaching, career snapshot, contact
- `resume` — page title, summary, all experience bullets, capabilities, education
- `work` — `/work` page and the `/work/:slug` case studies. Not preloaded in `src/i18n/i18n.js`; `useTranslation('work')` loads it on first visit to a case study
